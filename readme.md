# Gwen AI Agent

Локальный AI-ассистент для управления Windows-компьютером с помощью естественных команд.

Проект представляет собой персонального AI-агента, который использует локальную языковую модель через **Ollama** и может взаимодействовать с операционной системой с помощью набора инструментов.

Пользователь пишет команду обычным языком, модель определяет, нужно ли использовать инструмент, вызывает необходимую функцию, получает результат и формирует ответ.

> Проект находится в активной разработке. Архитектура постепенно расширяется от простого чат-бота с функциями управления ПК к полноценному локальному AI-агенту.

---

## Возможности

На текущем этапе Gwen умеет:

* получать текущее время;
* получать текущую дату;
* открывать приложения Windows;
* понимать некоторые русские названия и сокращения приложений;
* изменять громкость компьютера;
* включать и выключать звук;
* сворачивать и разворачивать окна через `Win + D`;
* делать скриншоты экрана;
* открывать разделы Steam;
* запускать игры через Steam;
* самостоятельно выбирать подходящий инструмент на основе команды пользователя;
* сохранять историю текущего диалога во время работы программы.

# Как это работает

Основная идея проекта:

```text
Пользователь
     ↓
   Agent
     ↓
  Ollama
     ↓
Языковая модель
     ↓
Нужен инструмент?
   ↙        ↘
 Да          Нет
 ↓            ↓
Tool       Обычный
 ↓          ответ
Результат
 ↓
Ollama
 ↓
Ответ пользователю
```

Например, пользователь пишет:

```text
Открой калькулятор
```

Gwen передаёт сообщение локальной модели.

Модель понимает, что для выполнения команды необходимо использовать инструмент:

```text
open_app
```

с аргументом:

```text
name_app = "калькулятор"
```

После этого `Tool Manager` запускает соответствующую Python-функцию.

Результат возвращается модели, после чего Gwen сообщает пользователю, что приложение было запущено.

# Описание модулей

## `main.py`

Главная точка запуска приложения.

Создаёт экземпляр `Agent` и запускает основной цикл общения:

```text
Пользователь → Agent → Ollama → Tool → Ollama → Ответ
```

Для выхода используется команда:

```text
выход
```

---

## `core/agent.py`

Главный мозг приложения.

`Agent` отвечает за:

* хранение истории текущего диалога;
* отправку сообщений модели;
* передачу модели доступных инструментов;
* обработку вызовов инструментов;
* получение результатов инструментов;
* формирование финального ответа.

Именно здесь находится логика взаимодействия между языковой моделью и инструментами.

---

## `core/tool_manager.py`

Центральный менеджер инструментов.

В нём находятся:

### `TOOLS`

Словарь, связывающий имя инструмента с Python-функцией:

```python
TOOLS = {
    "get_time": get_time,
    "get_date": get_date,
    "open_app": open_app,
    ...
}
```

### `TOOL_SCHEMAS`

Описание инструментов для языковой модели.

Модель получает информацию о:

* названии функции;
* назначении;
* аргументах;
* типах аргументов;
* обязательных параметрах.

### `execute_tool()`

Получает название инструмента и аргументы, после чего запускает соответствующую функцию.

---

## `core/prompts.py`

Системные инструкции для языковой модели.

Здесь находится `SYSTEM_PROMPT`, который объясняет модели:

* кто такая Gwen;
* для чего используется ассистент;
* что необходимо использовать доступные инструменты;
* как отвечать пользователю.

# Инструменты

Все реальные действия Gwen над компьютером находятся в директории:

```text
tools/
```

Это позволяет добавлять новые возможности без переписывания всего приложения.

---

## `tools/system.py`

Системные функции Windows.

Содержит:

### `get_time()`

Возвращает текущее время.

### `get_date()`

Возвращает текущую дату.

### `set_volume(level)`

Устанавливает громкость компьютера от `0` до `100`.

Пример:

```text
Поставь громкость на 50
```

### `mute_volume()`

Переключает состояние звука.

Если звук включён, он выключается.

Если звук выключен, он включается.

### `collapse_win()`

Использует сочетание:

```text
Win + D
```

для сворачивания или восстановления окон.

---

## `tools/applications.py`

Отвечает за запуск приложений Windows.

Gwen ищет ярлыки `.lnk` в меню «Пуск»:

```text
%APPDATA%\Microsoft\Windows\Start Menu
%ALLUSERSPROFILE%\Microsoft\Windows\Start Menu
```

После этого строится словарь доступных приложений.

Для поиска используется:

* точное совпадение;
* поиск по части названия;
* `difflib.get_close_matches()` для приблизительного совпадения.

Также существуют алиасы:

```python
APP_ALIASES = {
    "телеграм": "telegram",
    "тг": "telegram",
    "дискорд": "discord",
    "дс": "discord",
    "блокнот": "notepad",
    "браузер": "chrome",
    "калькулятор": "calc",
}
```

Это позволяет использовать естественные названия:

```text
Открой тг
```

вместо обязательного:

```text
Открой Telegram
```

---

## `tools/screen.py`

Отвечает за создание скриншотов.

Используется библиотека `PyAutoGUI`.

Скриншоты сохраняются в:

```text
screens/
```

Файл получает имя примерно такого вида:

```text
screen_20260914_163012.png
```

Папка создаётся автоматически при необходимости.

---

## `tools/steam.py`

Отвечает за взаимодействие со Steam.

### Открытие разделов Steam

Поддерживаются:

```text
библиотека
друзья
магазин
настройки
```

Также поддерживаются английские варианты:

```text
library
friends
store
settings
```

Для открытия используются Steam URI:

```text
steam://open/games
steam://open/friends
steam://store
steam://open/settings
```

### Запуск игр

Игры запускаются через:

```text
steam://rungameid/<APP_ID>
```

В проекте используется словарь Steam-игр с их AppID.

Также можно передать непосредственно числовой AppID.

# Добавление нового инструмента

Одна из главных целей архитектуры проекта заключается в том, чтобы новые возможности можно было добавлять отдельно.

Например, если необходимо добавить управление яркостью монитора, можно создать:

```text
tools/brightness.py
```

и написать функцию:

```python
def set_brightness(level: int):
    ...
```

После этого функцию необходимо зарегистрировать в:

```text
core/tool_manager.py
```

в словаре:

```python
TOOLS = {
    ...
    "set_brightness": set_brightness,
}
```

А затем добавить описание инструмента в:

```python
TOOL_SCHEMAS
```

После этого языковая модель сможет понимать, когда необходимо использовать новый инструмент.

# Почему используется такая архитектура

Изначально проект представлял собой большой Python-файл, в котором находились:

* логика AI;
* системный prompt;
* функции Windows;
* запуск приложений;
* управление громкостью;
* скриншоты;
* Steam;
* описание инструментов;
* основной цикл программы.

Такой подход удобен для первого прототипа, но по мере роста проекта становится сложно поддерживать код.

Поэтому проект был разделён на несколько уровней.

```text
main
 ↓
Agent
 ↓
Ollama
 ↓
Tool Manager
 ↓
Tools
 ↓
Windows / Steam / Applications
```

Теперь каждый компонент отвечает за свою задачу.

Это позволяет постепенно расширять проект, не превращая `main.py` в файл на несколько тысяч строк.

# Agent Loop

Текущая архитектура уже использует взаимодействие:

```text
User
 ↓
Agent
 ↓
LLM
 ↓
Tool Call
 ↓
Tool Result
 ↓
LLM
 ↓
Final Response
```

Например:

```text
Пользователь:
"Поставь громкость на 30%"
```

Модель определяет:

```text
set_volume(level=30)
```

Python выполняет функцию:

```text
set_volume(30)
```

Функция возвращает:

```text
Громкость установлена на 30%.
```

Результат снова передаётся модели.

После этого модель формирует ответ пользователю.

# Ограничения текущей версии

Проект пока не является полностью автономным AI-агентом.

Текущая версия имеет ряд ограничений:

* набор инструментов пока небольшой;
* список Steam-игр частично задан вручную;
* запуск приложений зависит от наличия ярлыков в меню «Пуск»;
* проект ориентирован на Windows;
* память пока не реализована как отдельная полноценная система;
* файловая система пока не подключена как полноценный набор инструментов;
* полноценный многошаговый Agent Loop находится в разработке;
* голосовой интерфейс пока не является частью основной архитектуры;
* нет полноценного интерфейса с GUI.

# Безопасность

Gwen получает возможность выполнять действия непосредственно на компьютере пользователя.

Поэтому добавление новых инструментов требует осторожности.

Особенно опасными могут быть инструменты, которые:

* удаляют файлы;
* запускают неизвестные программы;
* выполняют команды терминала;
* изменяют системные настройки;
* работают с сетью;
* изменяют конфигурацию Windows.

При дальнейшем развитии проекта планируется добавить систему подтверждений для потенциально опасных действий.

Например:

```text
Gwen:
Я собираюсь удалить файл "example.txt".
Подтвердить действие? [Да/Нет]
```

* **Qwen3 8B** - используемая языковая модель;
* **PyAutoGUI** - создание скриншотов;
* **PyCaw** - управление системной громкостью;
* **COM / comtypes** - взаимодействие с Windows Audio API;
* **Steam URI** - запуск разделов и игр Steam;
* **Git** - контроль версий;
* **GitHub** - хранение исходного кода.
