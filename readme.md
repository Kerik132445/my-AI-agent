# Gwen AI Agent

Локальный AI-ассистент для управления Windows-компьютером с помощью естественных команд.

Проект представляет собой персонального AI-агента, который использует локальную языковую модель через **Ollama** и может взаимодействовать с операционной системой с помощью набора инструментов.

Пользователь пишет команду обычным языком, модель определяет, нужно ли использовать инструмент, вызывает необходимую функцию, получает результат и формирует ответ.

> Проект находится в активной разработке. Архитектура постепенно расширяется от простого чат-бота с функциями управления ПК к полноценному локальному AI-агенту.

---

## Возможности

На текущем этапе Gwen умеет:

* получать текущее время;
* получать текущую дату;
* открывать приложения Windows;
* понимать некоторые русские названия и сокращения приложений;
* изменять громкость компьютера;
* включать и выключать звук;
* получать текущее время и дату;
* открывать приложения Windows, понимая русские названия и сокращения (например, «тг», «калькулятор», «дискорд»);
* управлять громкостью (установка точного уровня, выключение/включение звука);
* сворачивать и разворачивать окна через `Win + D`;
* делать скриншоты экрана;
* открывать разделы Steam;
* запускать игры через Steam;
* самостоятельно выбирать подходящий инструмент на основе команды пользователя;
* сохранять историю текущего диалога во время работы программы.
* делать скриншоты экрана и сохранять их в папку `screens/`;
* открывать разделы Steam («библиотека», «магазин», «друзья», «настройки»);
* запускать игры через Steam (по названию или AppID, с автоматическим исправлением опечаток и транслитерации);
* получать список купленных игр пользователя через **Steam Web API**;
* **управлять файлами и папками**:
  * просматривать содержимое директорий;
  * искать файлы по названию (по всему диску `C:` или в заданной папке);
  * читать текстовые файлы и открывать файлы в системе;
  * создавать файлы с заданным текстом;
  * копировать и перемещать файлы;
  * создавать папки;
  * безопасно удалять файлы и папки (строго с предварительным подтверждением пользователя);
  * понимать как полные, так и относительные и естественные пути («Рабочий стол», «Загрузки», «Документы»);
* **использовать долговременную память**:
  * запоминать важные факты о пользователе между запусками программы;
  * воспроизводить сохранённую информацию о пользователе;
  * обновлять и удалять устаревшие факты;
* **выполнять цепочки действий** в многошаговом Agent Loop (до 20 итераций на запрос);
* самостоятельно выбирать подходящий инструмент или серию инструментов на основе команды пользователя;
* сохранять контекст текущего диалога во время работы программы.

# Как это работает

Основная идея проекта:

```text
Пользователь
     ↓
   Agent
     ↓
  Ollama
     ↓
Языковая модель
     ↓
Нужен инструмент?
   ↙        ↘
 Да          Нет
 ↓            ↓
Tool       Обычный
 ↓          ответ
Результат
 ↓
Ollama
 ↓
Ответ пользователю
```

Например, пользователь пишет:

```text
Открой калькулятор
```

Gwen передаёт сообщение локальной модели.

Модель понимает, что для выполнения команды необходимо использовать инструмент:

```text
open_app
```

с аргументом:

```text
name_app = "калькулятор"
```

После этого `Tool Manager` запускает соответствующую Python-функцию.

Результат возвращается модели, после чего Gwen сообщает пользователю, что приложение было запущено.

# Описание модулей

## `main.py`

Главная точка запуска приложения.

Создаёт экземпляр `Agent` и запускает основной цикл общения:

```text
Пользователь → Agent → Ollama → Tool → Ollama → Ответ
```

Для выхода используется команда:

```text
выход
```

---

## `core/agent.py`

Главный мозг приложения.

`Agent` отвечает за:

* хранение истории текущего диалога;
* отправку сообщений модели;
* передачу модели доступных инструментов;
* обработку вызовов инструментов;
* получение результатов инструментов;
* многошаговый цикл выполнения (Agent Loop до 20 итераций) для цепочек действий подряд;
* формирование финального ответа.

Именно здесь находится логика взаимодействия между языковой моделью и инструментами.

---

## `core/tool_manager.py`

Центральный менеджер инструментов.

В нём находятся:

### `TOOLS`

Словарь, связывающий имя инструмента с Python-функцией:

```python
TOOLS = {
    "get_time": get_time,
    "get_date": get_date,
    "open_app": open_app,
    ...
}
```

### `TOOL_SCHEMAS`

Описание инструментов для языковой модели.

Модель получает информацию о:

* названии функции;
* назначении;
* аргументах;
* типах аргументов;
* обязательных параметрах.

### `execute_tool()`

Получает название инструмента и аргументы, после чего запускает соответствующую функцию.

---

## `core/prompts.py`

Системные инструкции для языковой модели.

Здесь находится `SYSTEM_PROMPT`, который объясняет модели:

* кто такая Gwen;
* для чего используется ассистент;
* что необходимо использовать доступные инструменты;
* как отвечать пользователю.

# Модели

## `models/ollama_client.py`

Модуль отвечает за связь Python-приложения с Ollama.

В текущей версии используется модель:

```text
qwen3:8b
```

Взаимодействие с Ollama выполняется через Python-библиотеку `ollama`.

Основная функция:

```python
send_message()
```

Она получает историю сообщений и, при необходимости, список доступных инструментов.

# Память

## `memory/memory.py`

Модуль долговременной памяти ассистента.

Позволяет Gwen сохранять ключевые факты о пользователе между перезапусками программы в файл:

```text
memory/data.json
```

Содержит функции:

### `add_fact(fact)`

Сохраняет важную информацию о пользователе (например, интересы, цели, предпочтения). Предотвращает дублирование уже имеющихся фактов.

### `get_facts()`

Возвращает список всех сохранённых фактов о пользователе.

### `update_fact(old_fact, new_fact)`

Заменяет устаревший факт на актуальный.

### `delete_fact(fact)`

Удаляет конкретный факт из долговременной памяти, если пользователь попросил забыть его.

Все реальные действия Gwen над компьютером находятся в директории:

```text
tools/
```

Это позволяет добавлять новые возможности без переписывания всего приложения.

---

## `tools/system.py`

Системные функции Windows.

Содержит:

### `get_time()`

Возвращает текущее время.

### `get_date()`

Возвращает текущую дату.

### `set_volume(level)`

Устанавливает громкость компьютера от `0` до `100`.

Пример:

```text
Поставь громкость на 50
```

### `mute_volume()`

Переключает состояние звука.

Если звук включён, он выключается.

Если звук выключен, он включается.

### `collapse_win()`

Использует сочетание:

```text
Win + D
```

для сворачивания или восстановления окон.

---

## `tools/applications.py`

Отвечает за запуск приложений Windows.

Gwen ищет ярлыки `.lnk` в меню «Пуск»:

```text
%APPDATA%\Microsoft\Windows\Start Menu
%ALLUSERSPROFILE%\Microsoft\Windows\Start Menu
```

После этого строится словарь доступных приложений.

Для поиска используется:

* точное совпадение;
* поиск по части названия;
* `difflib.get_close_matches()` для приблизительного совпадения.

Также существуют алиасы:

```python
APP_ALIASES = {
    "телеграм": "telegram",
    "тг": "telegram",
    "дискорд": "discord",
    "дс": "discord",
    "блокнот": "notepad",
    "браузер": "chrome",
    "калькулятор": "calc",
}
```

Это позволяет использовать естественные названия:

```text
Открой тг
```

вместо обязательного:

```text
Открой Telegram
```

---

## `tools/screen.py`

Отвечает за создание скриншотов.

Используется библиотека `PyAutoGUI`.

Скриншоты сохраняются в:

```text
screens/
```

Файл получает имя примерно такого вида:

```text
screen_20260914_163012.png
```

Папка создаётся автоматически при необходимости.

## `tools/steam.py`

Отвечает за взаимодействие со Steam.

### Открытие разделов Steam

Поддерживаются:

```text
библиотека
друзья
магазин
настройки
```

Также поддерживаются английские варианты:

```text
library
friends
store
settings
```

Для открытия используются Steam URI:

```text
steam://open/games
steam://open/friends
steam://store
steam://open/settings
```

### Запуск игр

Игры запускаются через:

```text
steam://rungameid/<APP_ID>
```

В проекте используется словарь Steam-игр с их AppID.

Также можно передать непосредственно числовой AppID.

---

## `tools/steam_api.py`

Отвечает за работу со **Steam Web API**.

Позволяет получать актуальный список всех купленных и доступных пользователю игр непосредственно из профиля Steam.

### `get_owned_games()`

Выполняет HTTP-запрос к эндпоинту `IPlayerService/GetOwnedGames`.

Для работы используются переменные окружения из файла `.env`:
* `STEAM_API_KEY` — ключ доступа к Steam Web API;
* `STEAM_ID` — 64-битный идентификатор пользователя Steam.

Возвращает словарь формата `{"название игры": "appid"}`.

---

## `tools/files.py`

Модуль для работы с файловой системой Windows.

Поддерживает работу как с абсолютными путями, так и с относительными или понятными названиями системных папок через функцию `resolve_path()`:
* `рабочий стол` / `desktop` → папка Рабочего стола;
* `загрузки` / `downloads` → папка Загрузок;
* `документы` / `documents` → папка Документов.

### Доступные функции:

#### `list_files(name_dir)`
Возвращает список файлов и папок внутри указанной директории.

#### `find_files(name, directory=None)`
Выполняет рекурсивный поиск файла по точному имени. Если директория не указана, поиск ведётся по всему диску `C:/`.

#### `read_file(path)`
Читает текстовое содержимое указанного файла в кодировке UTF-8.

#### `open_file(path)`
Открывает файл в операционной системе стандартным ассоциированным приложением (`os.startfile`).

#### `create_file(path, content)`
Создаёт файл по указанному пути и записывает в него переданный текст.

#### `copy_file(source, destination)`
Копирует файл из одного места в другое.

#### `move_file(source, destination)`
Перемещает файл в целевую директорию.

#### `create_folder(path)`
Создаёт новую папку по указанному пути (включая создание промежуточных директорий при необходимости).

#### `delete_file(path)`
Удаляет файл. Является потенциально опасным действием: Gwen запрашивает явное подтверждение пользователя перед выполнением.

#### `delete_folder(path)`
Удаляет папку рекурсивно вместе со всем её содержимым через `shutil.rmtree`. Строго требует предварительного подтверждения пользователя.

* Python 3.14 или совместимая версия;

# Установка Ollama

Необходимо установить Ollama на компьютер.

После установки проверить:

```powershell
ollama --version
```

Затем скачать используемую модель:

```powershell
ollama pull qwen3:8b
```

Проверить наличие модели:

```powershell
ollama list
```

В списке должна присутствовать:

```text
qwen3:8b
```

Ollama должен быть запущен во время работы Gwen.

# Добавление нового инструмента

Одна из главных целей архитектуры проекта заключается в том, чтобы новые возможности можно было добавлять отдельно.

Например, если необходимо добавить управление яркостью монитора, можно создать:

```text
tools/brightness.py
```

и написать функцию:

```python
def set_brightness(level: int):
    ...
```

После этого функцию необходимо зарегистрировать в:

```text
core/tool_manager.py
```

в словаре:

```python
TOOLS = {
    ...
    "set_brightness": set_brightness,
}
```

А затем добавить описание инструмента в:

```python
TOOL_SCHEMAS
```

После этого языковая модель сможет понимать, когда необходимо использовать новый инструмент.

# Почему используется такая архитектура

Изначально проект представлял собой большой Python-файл, в котором находились:

* логика AI;
* системный prompt;
* функции Windows;
* запуск приложений;
* управление громкостью;
* скриншоты;
* Steam;
* описание инструментов;
* основной цикл программы.

Такой подход удобен для первого прототипа, но по мере роста проекта становится сложно поддерживать код.

Поэтому проект был разделён на несколько уровней.

```text
main
 ↓
Agent
 ↓
Ollama
 ↓
Tool Manager
 ↓
Tools
 ↓
Windows / Steam / Applications
```

Теперь каждый компонент отвечает за свою задачу.

Это позволяет постепенно расширять проект, не превращая `main.py` в файл на несколько тысяч строк.

# Agent Loop

Текущая архитектура уже использует взаимодействие:
Текущая архитектура поддерживает многошаговый цикл взаимодействия (Agent Loop до 20 итераций):

```text
User
 ↓
Agent
 ↓
LLM
 ↓
Tool Call
 ↓
Tool Result
 ↓
LLM
 ↓
Final Response
Agent (цикл до 20 шагов)
 ┌──→ LLM
 │     ↓
 │   Нужен инструмент?
 │   ├─ Да → Tool Call → Tool Result ──┐
 │   │                                 │
 │   └─ Нет ───────────────────────────┤
 └─────────────────────────────────────┘
       ↓
  Final Response
```

Например:
Например, для простого действия:

```text
Пользователь:
"Поставь громкость на 30%"
```

Модель определяет:

```text
set_volume(level=30)
```

Python выполняет функцию:

```text
set_volume(30)
```

Функция возвращает:

```text
Громкость установлена на 30%.
```

Результат снова передаётся модели.
Результат снова передаётся модели, и модель формирует финальный ответ пользователю.

После этого модель формирует ответ пользователю.
Если же пользователь просит составную команду (например, обновить факт или найти и прочитать файл), Gwen может совершить несколько вызовов инструментов подряд в рамках одного запроса.

# Безопасность

Gwen получает возможность выполнять действия непосредственно на компьютере пользователя.

Поэтому добавление новых инструментов требует осторожности.

Особенно опасными могут быть инструменты, которые:

* удаляют файлы;
* удаляют файлы и папки;
* запускают неизвестные программы;
* выполняют команды терминала;
* изменяют системные настройки;
* работают с сетью;
* изменяют конфигурацию Windows.

При дальнейшем развитии проекта планируется добавить систему подтверждений для потенциально опасных действий.
В Gwen уже внедрена система безопасности для работы с файлами:
* Удаление файлов (`delete_file`) и папок (`delete_folder`) **никогда** не выполняется сразу после первой просьбы.
* Системный промпт строго обязывает Gwen сначала запросить явное подтверждение пользователя (например, словами «да», «подтверждаю», «удаляй») с указанием конкретного пути или папки, и только после явного согласия инструмент вызывается.

Например:

```text
Gwen:
Я собираюсь удалить файл "example.txt".
Подтвердить действие? [Да/Нет]
```
